# Shared website consistency and release checks v1

October 11, 2026. Author: Codex. Scope: TryBiomod only. Starting source and freshly fetched shared main: `6c958928d92a8d509a094588cc383d595d9d7694`, no divergence. The three unrelated inventory drafts were preserved.

The owner requested a standing rule that every contributor's website changes propagate to all affected consumers. Root AGENTS.md and CLAUDE.md now point to docs/website-change-rule-v1.md. The rule covers product/stock/price/pack data, promo and affiliate attribution, visual assets, checkout, admin, measurement, search metadata, original COA delivery and deployment settings. It distinguishes current runtime overrides from static defaults, legitimate base/sale differences, and immutable historical purchase records.

Previously the documented main-branch production pipeline built without running the isolated regression suites. Added npm run check:release with an explicit maintained allowlist of 29 current suites, TypeScript and working/staged whitespace checks. The existing BIOMOD_DEPLOY=true production build entrypoint runs that gate before compiling. GitHub Website consistency runs it on pushes, pull requests and manual dispatch. The PR checklist and README link the same shared rule. This does not create branch protection or prevent a privileged person from bypassing the standard pipeline.

Validation before publication: all 29 isolated suites and TypeScript passed, then the actual production build passed through the new gate. No provider calls, customer records, payment attempts, form submissions or real emails were used for these checks. The work changes release tooling and instructions, not storefront design, prices, stock or customer data. Publication and exact live version verification are recorded in a separate versioned release receipt after deployment.
