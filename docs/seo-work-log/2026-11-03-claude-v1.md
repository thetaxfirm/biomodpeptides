## Change: old-domain /signup lands on /account instead of a 404

Problem: `biomodpeptides.com/signup/` is #2 for "biomod peptides" (also seen at #4 on Nov 2). The old-domain rule forwards it to `trybiomod.com/signup`, which returned 404, so anyone clicking that result hit a dead page and the URL could pass nothing on. Bing's title for it is "My Account - Biomod Peptides", the same page `my-account` already maps to `/account`.

Commit 3d08a6e, pushed to main as a normal fast-forward (main had not moved): `lib/legacy-routes.ts` adds `'signup': '/account'`. `tests/legacy-domain-routes-v1.cjs` now checks `/my-account` and `/signup` (with and without a trailing slash) permanently redirect to `/account`, that neither enters the sitemap, and that `/signup/extra` and `/sign-up` stay genuine 404s. The test fails on the previous code and passes on the new code.
