# TryBiomod aggregate traffic reporting v1

October 10, 2026. Author: Codex. Base and fetched shared main: `3741498c81ddcb0fa168c2204f8f4b33d0dd66a8`. This commit contains the implementation; a separate uncommitted search improvement and three unrelated inventory drafts are excluded. Scope: TryBiomod only.

## Delivered

Added private Store Administration > Traffic at https://trybiomod.com/admin. It reports accepted public page-view events by broad page and referral groups for seven or thirty completed UTC days. Partial activation day and today are separate. Missing history and failures are unavailable, not zero visitors. Sales diagnostics and promo attribution remain separate. No unique-visitor, conversion, revenue-attribution, ranking or AI-visibility gain is claimed.

A separate /api/metrics POST accepts exactly event=page_view plus fixed pageGroup and sourceGroup enums. It does not call store session or IP-rate-limit helpers. It stores only UTC-day/category totals and singleton cleanup health. No analytics cookies, IDs, customer records, product names, URLs, search terms, referrer strings or IP addresses are added. Browser transport and hosting/security logs remain outside this feature's storage contract. Server origin/fetch-site/body guards, GPC/DNT, readiness/admin/error/private-route exclusions, document-only QA opt-out (?measurement=off), visible completed-navigation deduplication and no automatic retries are implemented. Later in-document navigation is internal rather than re-credited to the initial source. Only reviewed product slugs qualify.

The atomic acceptance cap is 50,000 events globally per UTC day. It limits counts, not request costs or sophisticated bots. The current date plus 89 prior UTC dates are retained; recording/report reads clean old buckets. A custom worker delegates the existing framework fetch unchanged and adds an awaited daily cleanup at 09:00 UTC. The previous remote cron list was empty, so no existing schedule was replaced. Actual scheduled-handler retention behavior passed in an isolated built worker with local D1. The first real platform cron execution has not occurred/been observed yet; its production execution remains a follow-up check. Cleanup health was empty at the first production aggregate observation because no event or authenticated report had run.

The new public disclosure is on /privacy-policy. It describes only this reporting feature and does not certify the complete existing draft policy. Existing commerce/account cookies are not described as analytics cookies. Existing authorizations, inventory, prices, public product holds, lab reports and BiomodPro were unchanged.
