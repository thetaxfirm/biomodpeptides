# Payment return and uncertainty correction v1

October 10, 2026. Author: Codex. Scope: TryBiomod only. Base and freshly fetched shared main: cbc9686, with no divergence.

## Verified problem and change

The prior PaymentReturn loaded orders once and only displayed unpaid statuses. Its Verify payment callback showed a toast without updating the displayed order, so a verified paid result could remain visually pending. Already-paid orders disappeared from this page. The hosted-payment GET route also claimed no payment had been taken when its payment-verification call itself failed, a conclusion the route could not establish.

The return page now displays recent owned orders, including paid and fulfillment states; immediately applies an authoritative verification result; then refreshes the list. Failed refresh retains the verified result and a persistent Retry control. Loading, signed-out, initial failure and empty-account states are explicit. Single-flight guards prevent repeated verification clicks, and owner/version guards ignore stale responses after sign-out, account changes or unmount. No automatic reconciliation, payment initiation or retry of a charge was added.

The hosted-payment failure copy now states that payment status could not be confirmed and directs customers to check orders or contact Biomod before paying again. Existing owner checks, provider checks, escaped diagnostic detail, receipt arguments and security headers remain unchanged. The customer's actual payment state is not inferred from this presentation correction.

Affected files: components/store/account.tsx (PaymentReturn only); app/api/store/[action]/route.ts (one failure message); tests/payment-return-v1.cjs; tests/hosted-payment-error-v1.cjs; this log.
Affected URLs: /payment/return; /api/store/pay. Existing auth-return paths are preserved.
