## Change: product meta descriptions drop self-repeating and nested aliases

Problem: the product description builder repeated the product name as its own alias when the product had no search spellings, and nested the compound qualifier. Live search snippets, Open Graph, WebPage schema and llms.txt read "Buy SEMAX 10mg (Semax (ACTH 4–10 analog))", "Buy SELANK 10mg (Selank)" and "Buy Tesamorelin 10mg (Tesamorelin)". Semax and Selank are indexed in Bing, so these were the snippets searchers saw.

Commit daaec24, pushed to main as a normal fast-forward (main had not moved): `lib/seo-policy.ts` adds `descriptionAliases()`. It drops any alias equal to the product name and, when the compound identity is "<product name> (<qualifier>)", keeps only the qualifier. A compound qualifier that is not the product name (e.g. "PT-141 + Oxy (oxytocin)") is kept whole. A before/after dump of every product description showed exactly 10 changed (Semax, Selank, Tesamorelin, plus the unpublished SLU-PP-332, Acetic Acid and five HEAT listings whose names only lost a repeated copy); every other description is byte-identical, including all name-variant spellings. `tests/description-aliases-v1.cjs` (in the release gate) fails on the previous code and passes on the new code.
