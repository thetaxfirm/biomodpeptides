# October 9, 2026: search-engine and AI-assistant discovery v2

Author: Claude. Scope: TryBiomod. Owner direction (Oct 9): improve visibility across search engines and AI assistants. Parent commit: 79844ea.

## Problem

A Claude web search for "trybiomod research peptides" returned no trybiomod.com result, not even for the brand. The robots policy already admits all crawlers (verified with OAI-SearchBot, Claude-SearchBot, PerplexityBot, Bingbot and GPTBot user agents, all HTTP 200). There was no way to notify non-Google engines of new pages and no llms.txt.

## Changes

- IndexNow key file `public/7a2a2775e1f5d580b51600e5e34016f1.txt` and `scripts/indexnow-submit-v1.mjs`. The script reads the live sitemap and submits only those URLs to api.indexnow.org, which shares submissions with Bing, Yandex, Naver, Seznam and Yep. Bing's index also feeds ChatGPT search, Microsoft Copilot, DuckDuckGo and Yahoo. Run it after any deploy that adds or changes public pages.
- `/llms.txt` (llmstxt.org format), generated from `sitemapPaths` and the reviewed `pageInfo` metadata. It returns 404 unless indexing is enabled on the public origin. Held products, private routes and ineligible pages cannot appear. No new product claims.

## Hypothesis and metric

The brand and product URLs become discoverable to Bing-derived engines and AI search sooner. Measure: Bing Webmaster Tools indexed count (needs an owner sign-in, which agents may not create), `site:trybiomod.com` results on Bing, DuckDuckGo and Brave, and referrals from chatgpt.com, perplexity.ai, copilot.microsoft.com and claude.ai once first-party measurement exists. No ranking or AI-answer inclusion is claimed.

## Release 2: certificate facts in Product data and llms.txt

- Problem: product pages show matching-lot COA results, but the Product JSON-LD and llms.txt carried only compound, contents and CAS. Search engines and AI assistants read structured data and plain text first, so lot evidence (the site's main differentiator) was invisible to them.
- Change: `lib/certificate-schema.ts` adds certificate lot, reported purity, reported measured content, report date and the certificate PDF link as Product `additionalProperty`. llms.txt product lines append the same facts. This happens only when `batchStatus` is `matched`, the same rule the product page uses. Values are copied verbatim from the published records.
- Coverage of the 17 eligible products: 10 have a matching-lot certificate. NAD+ 500mg, Selank, Semax and Tesamorelin 10mg show lot mismatches. KPV 10mg, MOTS-c 40mg and SS-31 50mg have documentation pending. Those 7 publish no results. A matching COA for those lots is the largest documentation gap a buyer will notice.
- Data question for the owner: purity strings read like ">99.80% + 0.18%". The original PDFs probably print "±"; text extraction may have flattened it. Source records were left unchanged.
- Hypothesis: queries such as "BPC-157 10mg COA" and AI answers comparing suppliers can cite trybiomod's measured values. Metric: Search Console and Bing queries containing "coa", "purity" or "lab test" plus a product name, and AI referrals once measurement exists.
- Verification: tests/llms-indexnow-v1.cjs (matched lot publishes exact values; all 7 unmatched products publish none), tests/seo-v7.cjs, tsc, focused ESLint and the production build passed.
