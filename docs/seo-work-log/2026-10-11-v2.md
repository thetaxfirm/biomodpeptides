# Actionable administrator request inbox v1

October 11, 2026 Pacific. Author: Codex. TryBiomod only. Freshly fetched base/main f8be029eba433a52b4f1adfe775ae7e34cdc940e had no divergence; the three unrelated inventory drafts are untouched.

The owner could not tell how to handle customer messages because technical COA settings/outbox details appeared first and every request ended with an unclear status dropdown. Added a customer-first inbox with Needs attention, All, Resolved and Spam filters; name/email/subject/reference search; Reply by email; Start review; Mark resolved; reversible Move to spam/Reopen actions; saved-request details; and relevant COA status beside its customer request. Reply opens the administrator's email application for review and sending; it never sends automatically or marks a request answered. Affiliate status changes do not approve participation or assign codes. General notification-only records no longer show a misleading empty Original COA state.

COA settings and detailed activity remain available in an explicit disclosure below the inbox. Existing original-document matching, send authorization, deduplication and provider-acceptance wording are preserved. Accepted/duplicate records cannot be resent through the new controls. No records are automatically classified, closed, deleted or modified by rendering.

POST admin-request now validates the exact UUID, an allowed target status and the previously displayed saved status. An atomic compare-and-set prevents one administrator's stale screen from overwriting another administrator's decision. Missing/internal records return 404, stale reads return 409, and old clients without expectedStatus get a refresh instruction. Submitted content, owner, original timestamps and outbox remain immutable. Customer notification views use readable workflow labels too. No new migration is required.

Validation: 31 isolated release suites, TypeScript and the actual gated production build passed. New route+SQLite tests cover both administrator roles, supported kinds, legacy states, exact validation, unauthorized/origin/body guards, concurrent writes, missing rows and no side effects. New component tests cover filters, search, explicit actions, safe reply/profile links, escaping, action locks and no duplicate sends. Existing admin owner/tenure/draft/read regression coverage was retained. Actual built Worker contact/affiliate lifecycle suite passed with all authentication/email services mocked. Independent backend review found no blocker.

Browser clicks on real components with synthetic data verified Start review, resolve, filter counts, reversible spam, reopen, case/space-insensitive search and the COA disclosure.
