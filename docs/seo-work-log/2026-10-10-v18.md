## Reproduced conversion defect

An isolated test of the actual StoreProvider and Cart reproduced a lost-item failure. Starting with an empty cart, adding BPC-157 persisted successfully. When the following state GET failed, the client still showed an empty cart. After transport recovered, adding MOTS-c sent a replacement containing only MOTS-c, removing the first saved item. Root independently reproduced the same sequence in a real browser with actual React components and a loopback-only fixture. This proves the failure mode, not that it caused any historical customer's pending order or lost sale.

## Correction

A successful cart POST now immediately adopts only its authoritative cart and totals. A failed follow-up read preserves that confirmed result and presents a GET-only retry, including after a confirmed empty save. A lost or rejected POST response is treated as unconfirmed: further cart writes and checkout are blocked until an accepted state GET reconciles it. The mutation is never replayed automatically. All cart mutations queue, use current execution-time data, and reject replacement snapshots that became stale while waiting. Reads begun before or during a write cannot later overwrite its accepted result. Observed owner changes, owner A/B/A changes and provider lifecycle changes invalidate queued work and late results.

Public refresh promises reject discarded reads instead of pretending current totals loaded. This preserves the existing PromoCode recovery lock when a superseding read fails. Checkout invalidates a delivery quote while cart writes are pending. Aggregate shopping measurement excludes uncertainty screens and in-flight non-add stages; accepted additions retain their persistence-boundary measurement where the existing eligibility and read-health rules allow it. No customer, product, price, code, order or payment identifier is added to analytics.

The server response has no owner/session/cart revision. These frontend guards do not establish cross-tab compare-and-swap protection or cover unobservable session changes. No payment gateway, order state, admin password, inventory, product identity, pricing or publication hold was changed.
